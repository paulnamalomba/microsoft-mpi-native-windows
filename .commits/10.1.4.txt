## [10.1.4.0] - 2026-10-17 (re-seed)

Decision
========

The user decided on 2026-10-17 that the fork's builds report themselves as
10.1.4.x, the version after Microsoft's 10.1.3, and that each of major,
minor and build is a single digit. This replaces the unbuilt seed 10.2.0.0
and its 0-99 build range. No build was ever accepted under 10.2.0.0, so no
accepted identity is renumbered or relabelled.

- Seed: 10.1.4.0, unbuilt. It is not a release or a passing-build claim.
- First qualifying build: 10.1.4.1.
- Ranges: major 0-9, minor 0-9, build 0-9. Carries reset the following
  fields: 10.1.4.9 -> 10.1.5.0, 10.1.9.9 -> 10.2.0.0, 10.9.9.9 -> 11.0.0.0.
  Each carry opens a new family note and invokes create-commit-notes.
- Shipped identity: native builds stamp the candidate version and source
  commit into the msmpi.dll, mpiexec.exe and smpd.exe VERSIONINFO resources,
  MPI_Get_library_version and the mpiexec banner. The resources do not
  name Microsoft as company or product.
- Unchanged upstream fields: ProductMajorVersion, BuildMinorVersion,
  MSMPI_VER and MSMPI_VER_EX. They feed the mpi.h ABI, the NetworkDirect
  connect handshake (ch3u_nd1_adapter.cpp) and trace fields.
- Publication: each accepted build is published as GitHub release
  native/v<version> of this fork, with one runtime-and-SDK zip, after the
  user confirms that publish.

Identity stamping (toward 10.1.4.1)
===================================

Version progression: none (10.1.4.0; counter 0 -> 0). Native builds stamp a
candidate; acceptance stays a separate step.

- native/build.py: NextVersion() (single-digit carries), NativeIdentity()
  (candidate default = next after MSMPI_INTERNAL_VERSION; it must follow the
  accepted version; source = short commit plus -dirty; attempt = local or
  ci<GITHUB_RUN_ID>.<attempt>), WriteIdentityHeader() (generated
  out/<cfg>-x64/native-identity/msmpi_native_version.h and identity.json),
  and GlobalProperties(configuration, native), which passes MsmpiNativeInclude
  and MsmpiNativeRoot. Option: baseline --candidate. The library string must
  stay under MPI_MAX_LIBRARY_VERSION_STRING (64).
- src/mpi.props SetMSMPIVersion: native-gated ClCompile include directory and
  MSMPI_NATIVE_IDENTITY=1. Upstream MSMPI_VER and MSMPI_VER_EX are unchanged.
- native/version.rc (new): one VERSIONINFO template. MSMPI_NATIVE_TARGET
  selects msmpi.dll (1), mpiexec.exe (2) or smpd.exe (3). FILEVERSION and
  PRODUCTVERSION carry the candidate; ProductVersion is
  <version>+<source>.<attempt>. CompanyName is "microsoft-mpi-native-windows
  (independent fork)", ProductName "MS-MPI native Windows fork", and
  LegalCopyright keeps Microsoft's line plus the MIT License. Comments name
  the 10.1.12498.16 source, the commit and the repository. Each of
  msmpi.vcxproj, mpiexec.vcxproj and smpd.vcxproj gets it as a native-gated
  ResourceCompile item. Upstream's .rc files need the WDK common.ver, and
  the public build never compiled them, so these binaries had no version
  resource before.
- src/mpi/msmpi/api/mpi_env.cpp MPI_Get_library_version: native branch
  returns MSMPI_NATIVE_LIBRARY_STR, e.g. "MS-MPI native-windows 10.1.4.1
  (source bf07f01)".
- src/mpi/mpiexec/mp_parse_command_line.cpp mp_print_options: the product
  name, version arguments and support line are macros. Native builds print
  "MS-MPI native-windows Startup Program [Version 10.1.4.1] (source ...)",
  and the issue tracker replaces askmpi@microsoft.com. Upstream output is
  unchanged when MSMPI_NATIVE_IDENTITY is undefined.
- native/verify.py: VersionStrings() reads VERSIONINFO through version.dll.
  IdentityChecks() requires the fixed and string versions and
  OriginalFilename in all three binaries, no claim to be Microsoft's company
  or product, the probe's library string, and the mpiexec -help first line.
- Results (local, dirty tree bf07f01-dirty): build baseline
  20261017T050148Z 22/22; verify 20261017T050315Z 16/16 (11 earlier checks
  plus 3 VERSIONINFO, library string and banner); check_abi exit 0, with 0
  unexplained differences.
